# 客体着色器缓存导入（社区数据 / 用户自带）

10-27 起，出包会自动并入两类现成的着色器缓存：我们收集的社区缓存，和玩家自己从别的模拟器带来的缓存。不需要任何开关。

## 放在哪

| 来源 | 目录 | 由谁放 |
|---|---|---|
| 社区 | `~/.s2arm/data/community_shcache/<目录>/<程序号大写>/`，`<目录>` 列在 `S2A_GUEST_CACHE_DIRS`（缺省 `totk_yuzu_v10_1027`） | 维护方 |
| 用户 | `~/Library/Application Support/S2Arm/着色器缓存/<程序号大写>/`（`S2A_USER_SHCACHE` 可改） | 玩家，经启动器「导入着色器缓存」 |

程序号就是游戏的 16 位 title id，例如0100F2C0115B6000是 `0100F2C0115B6000`。

## 版本门控（只管社区缓存）

缓存要和游戏版本一致才有用（10-27 维护者定）。

- 社区缓存入库时，在 `<程序号>/version.tsv` 登记录制版本：`versions<TAB>1.0.0 1.1.0`，再一行 `source<TAB>来源说明`。
- 出包时读原件的 `display_version`（`unpack.tsv`）。在登记的版本里才并入；不在、或者没登记，都不并，日志打一行 🟡「版本不符未并入」。
- 用户自己导入的缓存默认和他的游戏同版本，照旧自动并入，不门控。
- 现状：0100F2C0115B6000这份登记为 1.0.0 / 1.1.0（2023-05），我们的原件是 1.4.3，所以缺省不并。

## 认得的格式

- **yuzu 系**：yuzu、Eden、suyu、sudachi 等的 `vulkan.bin` / `opengl.bin`，文件头 8 字节是 `yuzucach`。
  - 出包时由 `graphics/tools/shbake/guest_cache.py` 转成客体代码包，按内容指纹缓存，同一份只转一次。
  - 已核过的缓存版本：10。其它版本会试着按「恰好解到文件尾」认布局，认不出就报出来。
- **Ryujinx 新格式**：同一目录里有 `shared.toc` / `shared.data` / `guest.toc` / `guest.data`，原样整个目录放进去。
- **不用的**：`vulkan_pipelines.bin` 这类显卡驱动侧的管线缓存，里面是别人机器上编好的宿主代码，对我们没用，放了也不读。

## 并进去之后做什么

- 缓存里有、但本款静态抽取没有的着色器代码，按缺省状态翻译进**通用模式**的离线库，玩家第一次遇到时不用现编。
- 各阶段代码都已在静态抽取里的程序直接跳过：它们的组合关系由参考库（`.s2rl`）提供，代码用静态抽出的那份。
- **直连模式不用这类缓存**：直连库按「NVN 控制段 + 代码」寻址，模拟器缓存里没有控制段，离线翻出的条目运行时对不上。

## 出包日志里看什么

- 🟢 `并入社区 / 用户客体着色器缓存：<文件>（程序 N（计算 M））`
- 烘焙日志 `shbake --ref-guest：…各阶段代码静态已有（客体代码包）X、…新收 Y（翻成 Z）`
- 转不出的不中止出包，只跳过这一份：社区的报【红】（是我们的数据有问题），用户的报【黄】（是玩家的文件坏了），都写明原因。
- 每份缓存的内容指纹进着色器阶段的键（`-gc`）：换了缓存就重烘，没换不白烘。`S2A_GUEST_CACHE=0` 出不带缓存的对照包。

## 后续项

- 0100F2C0115B6000那份缓存独有的代码（10-27 对 1.4.3 静态抽取：6724 个程序），里面有没有运行期才生成的，现在分不开。分类读数：去掉头部主体对上 1、只差操作数 1384、都对不上 4979，多半是旧版本的着色器。等有了0100F2C0115B6000 1.4.3 的运行期首遇记录（我方安全网现编日志或 Ryujinx 真值局），拿来对一次：命中多，就把这份的登记版本放宽，或单独放行。

## 注意

- 缓存要和玩家的游戏版本一致才有用。版本不同的旧着色器会被翻进包，却永远不会被用到，只是让包变大。
- 社区缓存只在内部用，不外发。
