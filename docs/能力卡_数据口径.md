# 能力卡数据口径（#717 名单线权威合同）

> 10-30 起 `docs/名单_60帧/`、`docs/名单_60帧能力覆盖/`、`docs/名单_满屏比例/`、`docs/名单_能力强信号/` 是按款登记目录：每款一个 `<程序号>.tsv`（首行表头），表说明与表头在 `_表头.tsv`；读取端经 `tools/reglist.py` 合并成原单表同形，不同款的改动互不冲突。

#717「共用能力卡」的生成器（贡献者实现）只按本文件从仓内结构化源表取值；本文件只写有仓内来源的规则，没有结构化来源的写「暂无来源 → 未验」。
确认原文：#717 名单线回帖（10-28）。源表结构由 `tests/cap_card_sources_test.py` 校验（表在、列在、取值在枚举里）；改源表表头或枚举先改本文件和该单测。

## 1. 三轴与展示

| 轴 | 取值 | 含义 |
|---|---|---|
| `support` | `supported / unsupported / unknown` | 明确支持 / 明确不支持 / 无结论；只有明确且适用的来源可写 `unsupported` |
| `enabled` | `on / off / unknown` | 当前包已开 / 明确关闭 / 缺启用事实（缺日志不是关闭） |
| `verification` | `verified / failed / unverified / conflicting` | 本身份限定内通过 / 明确失败 / 缺有效证据 / 适用记录冲突 |

展示由生成器派生，消费者（#706 游戏库、#682 / #696 清单）只显示不重判：

| 条件 | 展示 |
|---|---|
| `support=unsupported` 且无矛盾证据 | 不支持：原因 |
| `enabled=on` 且 `verification=verified` | 已开已验（附证据限定：平台 / 比例） |
| `enabled=on` 且 `verification=unverified` | 已开未验；未验：具体缺口 |
| `enabled=on` 且 `verification=failed` | 已开；验证失败：原因 |
| `enabled=off` | 未开启（历史验证可另行显示，不写当前已开） |
| `enabled=unknown` | 未验：缺启用记录 |
| `verification=conflicting`，或轴间矛盾 | 未验：证据冲突（不按优先级掩盖） |

## 2. 身份

| 字段 | 来源 | 规则 |
|---|---|---|
| `programId` | 各表 `程序号` 列 | 16 位大写十六进制 |
| `buildId` | 各表 `构建号` 列 | main 的 Build ID 前 16 字节，32 位小写十六进制（`pack/stage_rewrite.sh` 用 `xxd` 取） |
| `targetPlatform` | `ios / macos` | 只有 `docs/名单_满屏比例/` 有 `平台` 列；其余表无平台列 → null |
| `packageDigest` | 暂无来源 | 一律 null；#704 中间产物摘要不能填 |

缺平台 / 包身份的登记只作限定引用，不冒充当前包已验。未知平台 / 摘要不当通配符。

## 3. 八键来源

表头指第一条不以 `#` 开头的行；`graphics/widen/tables/verified.tsv` 例外，表头写在注释行 `# 程序号	构建号	款	平台	登记日期	依据` 里（`平台` 列 F7 #1574 起：`apple` / `android`）。

### 3.1 fps60

| 轴 | 来源 | 规则 |
|---|---|---|
| `support` | 暂无来源 | `unknown`。能力覆盖表只作 `fpsLayers`，不升格为支持结论 |
| `enabled` | `runtime/fps/<构建号前16位>.tsv` | 文件在 → `on`；不在 → `off`（回原帧率，不是 `unknown`）。出包 `pack/stage_rewrite.sh` 按 `runtime/fps/${BID:0:16}.tsv` 拷进产物根，宿主 `runtime/src/fps.c` 的 `fps_on_at_start` 缺省开、只有 `S2A_FPS60=0` 才关。文件名 16 位小写十六进制，文件内 `build <同名>` 行与本包构建号不符时宿主整表不用 |
| `verification` | `docs/名单_60帧/` 列 `逻辑速度` | 按程序号 + 构建号找行。`绿` → `verified`；`红` → `failed`；`判不出` / `未验` / 无此行 → `unverified`。表头必须是现行 13 列（含 `逻辑速度` / `逻辑速度局`），缺列或旧 11 列是输入错误、报错退出，不当 unverified；取值不在四值枚举里同样报错（与 #696 已验收的严格解析一致，10-28 #717 裁定） |
| 证据引用 | 同表列 `逻辑速度局` | 关 / 开两局局目录，只进 `evidence`，不进输出正文 |

`逻辑速度` 的判法是 `tools/fps_speed_judge.py`（两局画面峰值速度比 ρ≈1 绿、≈帧率倍数红），表头注释写明「只有绿才算 60 帧达标」。60 帧名单里的其他判据（MARK 后帧率、整机 W、满屏占宽）不另算 verified。

`fpsLayers`（只作能力覆盖，不是达标状态）：

| 来源 | 列 | 取值 |
|---|---|---|
| `docs/名单_60帧能力覆盖/` | `L1交换间隔` / `L2引擎限帧` / `L3时间步` | 五档原样：`已具备 / 部分 / 缺 / 不需要 / 未知`。允许五档后接一段全角括注，如 `缺（据 R7，未实测）`；括注不是第六档，取括号前的档位，括注与 `L1依据` / `L2依据` / `L3依据` 一起进 `evidence`（`kind=capabilityRegister` 或 `sourceText`）。`未知` 展示为「未验：能力状态未知」 |

### 3.2 fullscreen

| 轴 | 来源 | 规则 |
|---|---|---|
| `support` | 暂无来源 | `unknown` |
| `enabled` | `graphics/widen/tables/verified.tsv` | 本款「程序号 + 构建号」有行 → `on`；无行 → `off`（整局 16:9 加黑边）。依据：`pack/stage_rewrite.sh` 命中行写进产物根 `widen_verified.tsv`，`runtime/src/widen.c` 的 `widen_verified` 只看该文件在不在 |
| `verification` | `docs/名单_满屏比例/` 列 `档位` / `平台` / `结论` | 一行一个（档位, 平台）限定。`结论`：`过` → `verified`；`不过` → `failed`；`未验` → `unverified`。不跨档位、不跨平台推广；本款没有任何行 → `unverified` |

`平台` 列现有取值 → `targetPlatform`：`Mac` → `macos`，`iPhone` → `ios`；`Duo` / `Duo 内屏` / `Duo 外屏 + 折叠` → `ios`（Duo 是 iPhone 机型，见第 6 节 3），比例留在 scope。

### 3.3 direct、online、controller、rumble、gyro、quickMenu

| 键 | 来源 | 三轴 | 原因文案 |
|---|---|---|---|
| `direct` | 暂无来源（`pack/stage_inputs/direct.tsv` 是出包阶段的源码输入声明，不是逐款登记） | `unknown / unknown / unverified` | 未验：缺启用记录 |
| `online` / `controller` / `rumble` / `gyro` / `quickMenu` | 暂无结构化实测登记 | `unknown / unknown / unverified` | 未验：缺启用记录 |

接口存在、单测通过、功能开关开启都不替代游戏 / 设备验证。出包元数据暂无结构化合同，`enabled` 取不到时为 `unknown`，不解析日志。

## 4. 固定原因文案

| 情况 | 文案 |
|---|---|
| fps60：`逻辑速度` 为 `判不出` / `未验`，或无行、无列 | 未验：缺逻辑速度判定 |
| fps60：`逻辑速度=红` | 验证失败：逻辑速度变快 |
| fpsLayers：某层 `未知` | 未验：能力状态未知 |
| fullscreen：该（档位, 平台）`结论=不过` | 验证失败：满屏比例不过 |
| fullscreen：该（档位, 平台）`结论=未验` 或无行 | 未验：缺该比例满屏读数 |
| `enabled=unknown`（direct、online 等五键） | 未验：缺启用记录 |
| 适用记录冲突或轴间矛盾 | 未验：证据冲突 |

## 5. 反例（合成夹具必须含）

| 输入 | 期望 |
|---|---|
| `runtime/fps/<构建号前16位>.tsv` 在，`逻辑速度=红` | `enabled=on`、`verification=failed`；展示「已开；验证失败：逻辑速度变快」，不得显示已开已验 |

## 6. 原未决项的名单线裁定（10-28）

1. **原生 60 帧款的 `enabled`**：`docs/名单_60帧/` 的行若「能力来源」以「游戏原生 60 帧」开头（现为 0100152000022000），`fps60.enabled=on`、`support=supported`，原因写「游戏原生 60 帧，无需帧率表」；不因缺 `runtime/fps/<构建号前16位>.tsv` 判成未开启。其余款仍按 3.1：有表即 on、无表即 off。
2. **60 帧名单的平台**：表头判据「真机正式直连包」即 iPhone 测试设备，`docs/名单_60帧/` 每行一律 `targetPlatform=ios`，可算 verified（`逻辑速度=绿` 时）；不推广到 macos。
3. **Duo 平台**：Duo 是 iPhone 机型（iOS），`targetPlatform=ios`；比例档 1.42 / 1.455 照原样留在 scope 里，不跨比例推广。

## 7. 发布缺省（全能力出包，维护者 10-29 07:0x：「把这些自适应满屏、解锁 60 帧能力都做成泛化默认支持的，只有强信号无法支持的时候才关闭，这才是全能力出包和咱们具备泛化通用移植能力的标准」）
