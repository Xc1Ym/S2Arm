# 排查手册：不满屏 / 宽屏异常

适用范围：在比 16:9 更宽的屏幕上（iPhone 约 19.5:9），画面只占中间 16:9、两侧黑边或残留，UI 被拉伸 / 错位，某一页的暗化层或背景只盖中间。

结论先行：先分清是「没开」还是「开了没画对」。没开多半是总开关——包内能力清单或已验证名单，表本身往往不缺。开了没画对是第三层包装层（graphics/widen）对某类绘制分错了类。另外要记住：现有满屏判据只认纯黑边，两侧是残留花纹时它会判「过」。

## 宽屏三层，先弄清楚

| 层 | 做什么 | 来源 |
|---|---|---|
| 第一 / 二层 | 改游戏侧的宽高比上限等启用点 | `graphics/widen/tables/<款>_<构建号>/` 下的启用表 `widen_enable.<档>.tsv`，或自动出表 |
| 第三层 | 包装层：16:9 一族渲染目标横向放宽 k 倍、视口同乘 k、透视投影的 x 乘 1/k | `graphics/widen/`（直连经 `graphics/nvn/widen_glue.inc` 调同一个核心） |

第三层不依赖逐款表，没有整套放宽表就缺省整套放宽。八方2、0100152000022000 都是第二层启用 0 个点、只靠第三层，多档比例读数都过。

| 某页两侧残留 | 中间 16:9 正常，两侧各约 260 像素是旧帧内容（白 / 黄绿撕裂色块），B / OK 键已被外推到屏幕边 | 0100152000022000 选轮胎页（真机 2867×1320；Mac 对照局同样有） |

## ② 用哪个工具、看哪几行

host.log 关键行（原文格式）：

| 看什么 | 行 | 怎么读 |
|---|---|---|
| 总开关结论 | `[s2a] 宽屏：本款在宽屏已验证名单（…），屏幕宽 W` / `不在宽屏已验证名单` / `满屏关 S2A_WIDEN_CAPS=0` | 先看开没开 |
| 第二层启用 | `[s2a] 宽屏：main N 个点，启用 M 个，屏幕宽 W，启用表 …` | M = 0 时全靠第三层 |
| 出图层几何 | `[s2a] 直连：出图层已挂到根视图 WxH 像素（宽高比 r，…）` | 屏幕实际比例 |
| 原比例页 | `出图原比例居中（16:9 原比例页，…留黑边，不判未满屏）（第 N 次出图起）` / `出图离开原比例页（第 N 次出图起）` | 进出 16:9 页的帧号；截图那帧在不在页里 |
| 未满屏红 | `出图未满屏` | 只对纯黑带判 |
| 包装层统计 | `S2Arm widen: submits …, draws … (into core …, rewritten …)` 和 `其中纯色 / 小图层按原样铺满 N、起 16:9 原比例页 …` | 「铺满」类规则整局有没有触发过 |

总开关优先级（`runtime/src/widen.c` 的 `widen_verified`），从高到低：

1. 环境变量 `S2A_WIDEN_VERIFIED=1/0`（判定局、单测用）
2. 用户设置 `S2A_WIDESCREEN=0`（iOS 由 App 设置转来）
3. 包内能力清单 `S2A_WIDEN_CAPS`（`pack/gen_caps.sh` 写）
4. 模块目录有没有 `widen_verified.tsv`（命中 `graphics/widen/tables/verified.tsv` 时由出包写入）

工具：

- `tools/widen_accept.py`：满屏验收。只认整列纯黑，两侧非黑残留会被当成内容判过（见根因 4）。
- `graphics/widen/scan/judge.py`：宽屏判官，看成对的 16:9 / 放宽证据，判拉伸、错位、界面越界、亮带、闪烁。
- `graphics/widen/scan/auto_table.sh`：自动出表。
- `tools/quality_check.py`：AI 看截图判 UI 错位、残留，作为满屏列的最终判读。

## ③ 常见根因（现象 → 根因 → 怎么认出来 → 修在哪）

### 1. 总开关没开（最常见）
- 现象：整局 16:9。
- 根因：包内能力清单满屏键为 0，它压过了已验证名单；或者款不在 `verified.tsv` 里。12 款正式包里真机实际开宽屏的只有 4 款，其余 8 款主要卡在这里，不是缺表。
- 怎么认：host.log 第一条宽屏行；把能力清单那个键和 `verified.tsv` 对一下。
- 修在哪：`pack/gen_caps.sh`、`graphics/widen/tables/verified.tsv`。已知缺陷：测试包生成能力清单时读的是旧产物根，所以新出的表不会让满屏键变 1。

### 2. 自动出表卡在 MARK
- 现象：自动出表 25 个「款×构建号」只过 1 个。
- 根因：探测局必须先到 MARK（自动玩家认定「已进可玩画面」），到不了就判不过、不再试点。可是「哪些点被执行到」只看 host.log 的首次命中，本来不需要 MARK。另外，局根本没起来（等负载超时、构建失败、链号不一致）时也会写 `verdict.tsv`，这次失败就被记成「不过」，并按工具版本冻结、不再重跑。
- 怎么认：`graphics/widen/scan/auto_table.sh` 的结果目录里看每格的 `verdict.tsv`、`run.out`。
- 修在哪：`graphics/widen/scan/auto_table.sh`、`closed_loop.sh`。

### 3. 拷贝进来的整屏副本没登记（喷3 暗化层）
- 现象：暗化底只盖中间 16:9。
- 根因：界面层铺满画布地采样一张 128×72 的模糊底。这张底的内容是整屏画面横向压了 k 倍，但它没被登记成「整屏副本」，于是被当成普通图片按原尺寸居中画。
- 状态：**定因中**。在 Mac 上用诊断查到：被采样的那张贴图从来没被直连后端拷贝或渲染写过，它是游戏贴图池里登记的那份贴图对象；模糊结果是画进另一张 128×72 渲染目标的。当前假设是两者共用同一块内存，但序号不同，宽屏核心按序号认不出它们是同一张。只按「整级整宽拷贝」登记整屏副本的修法，在实局里没生效。
- 修在哪：`graphics/widen/WidenSession.cs`（`CopyFilled` / `Root`）、`graphics/widen/WidenFrame.cs`、`graphics/nvn/widen_glue.inc`、`nvn_mtl.m` 的别名表（按 池 + 偏移 + 描述 共用存储）。

### 4. 铺满画布的底层没外推（0100152000022000 选轮胎页）
- 现象：两侧残留旧帧内容。
- 根因（**假设，未验证**）：这页铺满画布的底纹贴图既不是 ≤8×8 的小图，也没被认作平铺底纹，所以没被推到屏幕边，只画进中间 16:9。同一帧里也没有任何绘制或清屏写到两侧带，那里就留着之前的内容。
- 怎么认：截图那帧（真机第 1043 帧）不在任何原比例页里；整局统计「其中纯色 / 小图层按原样铺满」一直是 0。
- 修在哪：`graphics/widen/` 的界面层分类（居中层 / 铺满画布）。

### 5. 满屏判据只认纯黑（绿着失效）
- 现象：两侧明明是残留，验收却判「占宽 100、黑边 0、过」。
- 根因：`tools/widen_accept.py` 和宿主上屏的满屏判据都只检测整列纯黑，非黑的残留被当成内容。
- 怎么认：0100152000022000 Mac 对照局的轮胎页截图就被判成了过。
- 做法：满屏一列以 AI 看图为准；量具判过不代表画面对。

### 6. 第三层做不到的范围
- GL 直连：贴图创建时就定了宽度，运行中换不了比例。Vulkan 直连（10-30 起）：本层建的附件图像可重建存储——尺寸不属 16:9 一族的先记「未定」，上面有铺满视口、读到 16:9 镜头矩阵的绘制就按内容判成画布、下次提交重建成放宽存储（银河2 1920×1584 Wii EFB，graphics/widen WidenFrame.TryPromote + vk_widen.inc wd_promote）；运行中换屏（Duo 合上 / 展开）仍未接。
- 游戏 CPU 侧按 16:9 视锥剔除物体：边缘可能缺东西。
- 投影矩阵认不出：只能靠第二层（例如 d3）。
- 着色器按绝对像素坐标采样：没核过。

## ④ 代码在哪、单测怎么写

| 区域 | 文件 |
|---|---|
| 宽屏核心（分类、放宽、原比例页、整屏副本） | `graphics/widen/WidenSession.cs`、`graphics/widen/WidenFrame.cs`、`graphics/widen/export/WidenCApi.cs` |
| 直连胶水（贴图登记、绘制分类、拷贝登记） | `graphics/nvn/widen_glue.inc`、`graphics/nvn/gfx/nvn/nvn_mtl.m`（`copy_t2t`、`tex_widen`） |
| 总开关 | `runtime/src/widen.c` |
| 出包 / 能力清单 / 自动出表 | `pack/gen_caps.sh`、`pack/stage_rewrite.sh`、`graphics/widen/scan/auto_table.sh` |

先红后绿样板：

- `tests/visual/widen_unit/Program.cs`：核心单测，期望值全靠手算。整屏副本这类修法照这个写：先登记一张放宽源，再报一次「缩放拷进没放宽的贴图」，断言目标被记成整屏副本、绘制分类从居中层变成按 k 缩放；非整屏源要清掉登记；放宽过的目标不登记。这一组用例跟着喷3 修法一起合入，现在主线上还没有。
- `tests/visual/widen_gate.tsv`：九款录像金样。值是确定性的；漂了先二分定因，再写明原因重新登记，不放宽界限。

真实游戏上先在 Mac 局复现再改。Mac 局截图拿到的是出图窗口，可能只显示中间 16:9，两侧条带要靠诊断行读数判，或者看真机截图。
