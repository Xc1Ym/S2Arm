# 排查手册：花屏 / 贴图错 / 闪烁

适用范围：直连模式下画面出现噪点、色块、贴图错乱、整片发白 / 发黑、高光或局部闪烁。宽屏两侧的问题看 [不满屏与宽屏异常](不满屏与宽屏异常.md)，没走直连的看 [直连异常与退回通用](直连异常与退回通用.md)。

结论先行：这类问题的根因多半落在四处——GPU 读到了没人写过的旧字节、同一渲染过程里采样自己的附件、采样器状态没按游戏的 ABI 布局存、Metal 编译数学模式把 NaN 判断折叠掉了。每一处都有现成的 host.log 读数和单测样板。

## ① 症状长什么样

截图示例不进仓库（公开仓扫描禁止新增游戏截图），下面是文字描述；需要对照图时找维护者要。

| 症状 | 样子 | 实例 |
|---|---|---|
| 旧字节花屏 | 背景整片高反差黑白噪点、带残影轮廓，场景切换后出现，UI 本身正常 | 喷3 房间列表（真机，开 `DM_NVN_NONFINITE_FILL=1` 反证时必现） |
| 曝光锁白 | 切场景后整屏过曝发白，一直不恢复 | 喷3 广场切换（Mac 25 局里 15 局） |
| 回环采样闪烁 | 高光区域逐帧闪，同场景相邻帧亮度跳 | 0100000000010000 #100（报告者 M5 Pro；Spare-host M3 上修前也不复现） |
| 采样器状态错 | 远处贴图过糊 / 过锐、各向异性或偏置不对，且每 300 帧日志里大量「重新登记」 | 0100000000010000（旧布局每 300 帧 4800–6500 个） |
| 通道映射错（alpha 恒为 1） | 圆形光晕 / 软边出现方框状硬边、卡片或提示框整片发白；**远近都有**（不是 mip / LOD），换镜头不变 | 01007EF00011E000（2026-10 用户报；「远近都有」是**旧包**观测，当前包未复现，且闪退挡住未能实测）。同名形态此前在0100000000010000表现为硬边提示框 / 白金币卡 |

## ② 用哪个工具、看哪几行

先跑一局拿 host.log，按下面顺序 grep：

| 看什么 | host.log 行（原文格式） | 怎么读 |
|---|---|---|
| 图形模式 | `[s2a] 图形模式：直连（依据 …）` | 不是直连就转另一份手册 |
| 采样器重新登记 | `[dm] [nvn-mtl] sampler pool up to frame N: K IDs registered again with a different state` | 只在 K > 0 时打。正常应为 0；持续上千 = 采样器对象布局问题 |
| 同过程回环采样 | `same-pass feedback sampling up to frame N: X draws sampled their own pass's attachment: ① narrowed view a, ② read memory as it was b, ③ pass ended first c, ④ snapshot d (… MB copied)` | X > 0 说明有回环；四层各处理了多少 |
| 回环快照开关 | `same-pass feedback sampling snapshot: off (DM_NVN_FB_SNAP=0)` | 关快照对照用 |
| 通道映射（swizzle） | `TextureBuilderSetSwizzle not identity (r g b a): remapped with a Metal view when sampling` / `TextureViewSetSwizzle not identity (…)` | **零参数探针，不用先知道贴图尺寸。** 每次运行只打第一例：出现即说明这个游戏仍在建非恒等映射，四条值就是映射本身（NVN 枚举：0 零 / 1 One / 2 R / 3 G / 4 B / 5 A），`(R,0,0,1)` 打成 `2 0 0 1`，`(1,1,1,R)` 打成 `1 1 1 2`；一条都不出现 = 全程恒等，映射这条线不成立。局限：第一例未必是出问题那张贴图，只能做有 / 无的粗判，定位到具体贴图要用下面 `DM_NVN_TEXINFO` |
| 一次性红行 | `【红】` 开头 | 任何新出现的红行都先看 |

诊断开关（只做 A/B 对照，不进正式包）：

- `DM_NVN_NONFINITE_FILL=1`：恢复「把含 Inf/NaN 的旧存储当初始内容」的旧行为，用来反证旧字节类花屏。
- `DM_NVN_FB_SNAP=0`：关掉回环采样的第④层快照。
- `DM_NVN_SHOT=帧号[,帧号…]:路径`（路径里 `%d` 换成帧号）：直连模式逐帧连拍，判闪烁用。
- `DM_NVN_TEXINFO=<W>x<H>`：**按尺寸精确筛选**才打（`sscanf("%ux%u")` 且宽高都相等；不设、或写成别的形式 = 一条都不打，没有通配也没有「全打」）。注册行会带 `creation swizzle d:rgba` 与 `view swizzle`，前 40 条之后每 600 条一条。用法是先拿到目标贴图的精确宽高，否则这条开关什么都看不到。
- `NXGAL_FRAME_CAP`：只在通用模式（GAL 出图层）生效，直连模式写不出帧，别在直连局上用。

判读工具：

- `tests/visual/framecap_check.py <帧文件>`：逐帧量亮度跳变（整幅均值偏 > 1.5% 又跳回）和成片错位。镜头在动时加 `--motion`。注意它量的是整幅均值，局部高光闪烁要按块量或直接看连续帧。
- `tools/quality_check.py`：AI 看截图判花屏 / 贴图错 / 黑块 / 残影 / UI 错位，拿不准时对照同款 Ryujinx 参考截图。

## ③ 常见根因（现象 → 根因 → 怎么认出来 → 修在哪）

### 1. 旧字节里的 Inf / NaN（喷3 曝光锁白、房间列表噪点）
- 现象：场景切换后整屏发白或背景成片噪点，切回来也不恢复。
- 根因：游戏释放旧内存池，在同一块内存上建新的浮点贴图（喷3：256×256 R11G11B10F 立方体数组，13 个立方体 6 级）。内存里残留的 CPU 字节被当成贴图初始内容，其中 0.30–1.60 M 个是 Inf/NaN（共 6.87 M），曝光计算一旦吃到就锁死。
- 怎么认：Mac 25 局里锁白的 15 局都有这种填充，没锁白的 10 局贴图都落在全零新内存上。开 `DM_NVN_NONFINITE_FILL=1` 必现，关掉不现。
- 修在哪：`graphics/nvn/gfx/nvn/nvn_mtl.m` 的 `fill_nonfinite`。浮点贴图的存储里只要有 Inf/NaN 编码，就不当初始内容（正常的有限浮点数据不会含这些编码）。

### 2. 采样器对象布局（0100000000010000重新登记）
- 现象：每 300 帧打一行「sampler pool … K IDs registered again」，K 上千。画面上表现为采样状态时对时错。
- 根因：游戏自带采样器缓存，按对象**从字节 8 起**算 CRC 判断是否同一个采样器。我方状态没全放进 [8,0x30)，或者有未初始化字节，CRC 每次都不同，缓存就一直当新对象重建、重新登记。
- 怎么认：上面那行读数；修后同存档同路线应为 0（0100000000010000 Spare-host M3，9 局全 0）。
- 修在哪：`graphics/nvn/gfx/nvn/nvn_obj.h` 的 `samp_par` / `samp_t`，所有状态放进 [8,0x30)；`hle_nvn.c` 初始化时清 pad。合入提交 f3b8f8a96。

### 3. 同一渲染过程里采样自己的附件（回环采样）
- 现象：高光 / 反射区域闪烁，或画面局部是上一帧的内容。
- 根因：一笔绘制采样的贴图正是当前渲染过程的附件。Metal 上这是未定义行为，不同代 GPU 表现不同（Apple10 尤其敏感，Apple9 上常常看不出来）。
- 怎么认：`same-pass feedback sampling` 那行 X > 0。
- 修在哪：`nvn_mtl.m` 的 `fb_prepare`，按四层依次处理：① 收窄视图（附件和采样区不重叠时只取不重叠的级 / 层）、② 读内存原样（没写过的直接读）、③ 先结束本过程、④ 快照拷一份。另外两条：按每笔绘制隔离快照槽，进四层之前先落地挂起的清屏。对全部游戏缺省生效，合入提交 e363e2ee3。
- 验法：同一台机器修前必须能复现，不然修了也证明不了。0100000000010000在 Spare-host M3 上修前不复现，只能请 M5 用户复验。

### 4. Metal 数学模式把 NaN 判断折叠掉
- 现象：本该被 `isnan` 挡掉的值漏过去，出现黑块 / 白块；不同编译路径（离线库 / 设备现编）结果不一致。
- 根因：fast-math 下编译器把 `isnan(x*0)`、`isnan(x-x)` 折叠成常量 false。
- 怎么认：`graphics/metal/tests/t_mathmode.m` 的 6 个判定项。
- 修在哪：`graphics/metal/gal_prog.m` 的 `gal_msl_opts()` 用 `MTLMathModeRelaxed` + `preserveInvariance`，`graphics/metal/tools/gal_offline.py` 离线编译用同一组参数。注意：和 NaN 做有序比较，在 relaxed 下照样会被折叠，只有 safe 模式才保住；单测里这两项只打印不判。

### 5. 采样器偏置 / 归约在旧 GPU 上要模拟
- 现象：Apple9（M3 / A17 一代）上远景偏糊或偏锐；首次画到某个着色器时卡一下。
- 根因：Apple9 没有原生的采样器 LOD 偏置 / 归约，要在着色器里模拟。按变体出会让包体积膨胀（静态全集 +72%）。
- 现状：在做终版——偏置改为主体着色器从常量读，归约 348 键出包期出变体。这一条还没合入，按「进行中」看待。

### 6. 判据会绿着失效
- 金样漂移：`tests/visual/widen_gate.tsv` 的登记值是确定性的。一旦漂了，先二分到具体提交，确认是那次改动正当带来的，再写明原因重新登记；不准为了变绿直接放宽界限。（丝之歌帧 30：500687/4231176 → 500688/4231178，二分到 394cb6858 合编批次组成变化，重登记提交 d43f7b393。）
- 整幅亮度量不到局部闪烁：0100000000010000连拍 150 帧，整幅「跳变又跳回」修前修后都是 0 帧，所以局部问题要按块量或直接看图。
- 报绿要同时报射程：扫了几局、几帧、分母多少。

## ④ 代码在哪、单测怎么写

| 区域 | 文件 |
|---|---|
| 直连 Metal 后端（贴图、采样器、渲染过程、回环） | `graphics/nvn/gfx/nvn/nvn_mtl.m` |
| NVN 对象布局（采样器 / 贴图 ABI） | `graphics/nvn/gfx/nvn/nvn_obj.h`、`graphics/nvn/gfx/nvn/hle_nvn.c` |
| MSL 编译参数 | `graphics/metal/gal_prog.m`、`graphics/metal/tools/gal_offline.py` |
| 着色器加载与共用构造 | `nvn_mtl.m` 的 `shader_load_depth` |

先红后绿：先写一个在旧代码上红的单测，再改到绿。样板：

- `graphics/nvn/tests/t_nvn_samp.c`：采样器 ABI。构造游戏视角的对象，从字节 8 算 CRC，断言同状态 CRC 相同、改一个字段 CRC 变。
- `graphics/nvn/tests/t_nvn_red.m`：偏置 / 归约模拟。原生一路和模拟一路的输出逐位比。
- `graphics/metal/tests/t_mathmode.m`：数学模式。每个折叠陷阱一个判定项。
- `graphics/nvn/tests/t_nvn_shader_flight.m`：真 Metal 并发加载 + GPU 输出核对。

写法：期望值必须能不跑被测实现就算出来；负对照（例如把修复关掉）必须红。
