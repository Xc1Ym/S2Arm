# G06：iPhone / iPad 与 Mac 手动迁移存档

关联 #97，使用 [G05 的 S2ArmSave v1 格式](存档备份_G05.md)。双方必须使用同一游戏、本体/更新版本和 DLC 组合；账号存档已有归属不同会拒绝恢复。迁移不合并进度，也不自动同步。

## 使用

1. 先在游戏内保存。四指长按打开设置，在「存档」中选择「管理存档…」，确认「已保存，退出游戏」，然后重新打开 App。也可以在系统设置的当前 App 中开启「下次打开时管理存档」，关闭并重开 App。
2. 在游戏尚未启动的管理页面，选择「导出当前存档…」，用系统文件选择器保存 `.s2asave`。在 Mac 启动器的游戏详情 →「存档备份与恢复…」选择该文件检查并恢复。
3. Mac → iOS 时，先从 Mac 同一页面导出备份。将文件通过“文件”可访问的位置传到设备，选择「选择备份并检查…」。检查通过会显示游戏、原始版本号、备份时间、账号、文件数和大小，确认后恢复。
4. 恢复前会留下原目录和 `before-restore.s2asave`；可用「导出恢复前备份…」保存最近一份。此前没有存档时不会生成空备份。恢复成功后选择「开始游戏」检查进度。

原副本不会自动清理。导入失败后请重新选择和检查；不要删除 App 来重试。游戏内尚未提交的进度无法由退出操作补存。

旧安装包缺少可信游戏身份时，管理页会提示从新版 Mac 启动器重新出包，仍允许正常启动既有游戏。若存在无法恢复的事务，则阻止启动并保留现场。

## 实现边界

- `pack/save_identity.py` 使用原始 NSP/XCI 的实际检查结果和 SHA-256，复用 `selected_packages` / G05 `identity`，将 `save-identity.json` 随 App 签名封装。身份摘要进入出包缓存键，因此已有的一键出包产物会重出一次；相同输入的身份不变，后续仍可命中缓存。仅从预提取资源出包、没有原始身份时，不猜内容身份，也不复用输出目录内其他来源的身份文件。
- 原生界面只在启动前调用 `S2A_SaveTransfer` / `S2A_SaveTransferFree`。`Host.Boot` 与桥接共用门锁；初始化开始后拒绝迁移，初始化失败且尚未发布设备时释放屏障。管理页在主线启动续体被领取前进入；选择「开始游戏」后恢复加载页，再由同一续体启动宿主。
- 服务层通过 P6 的 `IHostDirectoryTransaction` 读取普通文件和同步目录，不导入平台 libc。苹果生产装配在 `services/aot/Compose.cs` 的模块初始化中登记真实 provider，早于存档管理和 `Host.Boot`；未登记时返回 `save_unsupported_runtime`，不创建事务目录。安全读取由 provider 执行 `O_NOFOLLOW | O_NONBLOCK` 和打开后的普通文件检查，返回的 `SafeFileHandle` 交给 `FileStream` 持有，构造失败时立即释放。
- 运行中的管理入口复用统一设置页，由真实游戏宿主提供确认操作；没有游戏能力的独立工作台不显示存档组。确认弹窗沿用保存提醒和退出后重开流程，不接入尚未合入的进程内重启。
- 数据根与服务层相同，为 `Documents/S2A/ryujinx`（显式 `S2A_RYU_DATA` 优先）。事务位于同级 `save-transfer`，导出文件位于 `save-exports`。iOS 的 `/var` 路径先规范为实际容器路径；存档内部的链接继续拒绝。
- 存档索引由固定依赖 LibHac 0.19.0 的公开 `FlatMapKeyValueStore` 解析，不能按当前 profile 猜归属。只导出 G05 白名单；缓存、游戏资源、密钥和日志不进入备份。恢复保留白名单外的数据。
- 先完整检查备份和目标散列，确认时再次检查；恢复前备份与新目录写盘完成后，使用同盘重命名与事务记录提交。进程中断后，未提交状态回退，已提交状态保留新数据；不能确认状态时阻止启动。
- ZIP 按公开 EOCD / ZIP64 和中央目录格式，在 `ZipArchive` 分配条目前检查数量、大小、单卷、头部一致性及数据范围，再由公开的 `ZipArchive` 解码并核 CRC/SHA-256。只接受存储和 Deflate 压缩；不调用 .NET 内部 ZIP API。
- 文件选择器默认打开本 App 的文稿目录，也可切换到其他位置。导入检查拒绝、取消、恢复结束及导出选择器完成/取消后清理本次临时副本；恢复前备份和用户选择的源文件保留。进程被强制关闭时留下的临时文件可能需要手动清理。
- `deviceSettings` 按 G05 校验、在导入预览中说明其行为。首版不自动改变本机时钟、语言、地区或时区，也不调用 `S2A_SAVE_DIR` 测试播种接口。时间敏感游戏仍须检查实际游戏行为。

## 验证方法

第一层通过 LibHac 的实际文件系统 API 创建并提交账号和设备存档，内容为仓库公开文本；调用 G05 CLI 与 G06 生产接口验证双向恢复、目录/散列/归属一致，以及 ZIP64、流式数据描述符和拒绝路径。不需要游戏或玩家进度：

```sh
bash tests/save_transfer_interop_test.sh
```

真实存档和游戏身份均放在仓库外或忽略的构建目录，不提交玩家数据。第二层定向验证入口：

```sh
S2A_SAVE_TRANSFER_SOURCE=/absolute/real-ryujinx-root \
S2A_SAVE_TRANSFER_GAME=/absolute/save-identity.json \
S2A_SAVE_TRANSFER_MAC_ARCHIVE=/absolute/mac-export.s2asave \
bash tests/t_save_transfer_real.sh
```

测试只读原存档，在临时副本上检查文件往返、原副本保留、身份和完整性拒绝、确认后变化，以及四个持久化边界的真实子进程强制退出和恢复。需要自有数据的此项列为二层检查；`tools/contrib_check.sh` 单独报告一级自检。

文件往返、NativeAOT 编译和实际设备游戏读档分别记录，不能互相代替。真实断电和所有文件系统的持久性不在进程退出测试的证明范围内。
