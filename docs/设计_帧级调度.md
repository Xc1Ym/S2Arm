# 帧级命令调度（设计稿，帧率能耗线 10-21）

## 要解决的事
渲染器按 GAL 命令顺序一对一编码：渲染遍开着时来了一条遍内做不了的操作（写缓冲、拷贝、派发、贴图上传、落实清屏、索引转换……），就只能收遍，附件整张存回再读入（iPhone 上是片外带宽）。
过去逐类补（镜像 / 预载 / 暂存补丁三道 + 两遍合一），换一款就漏。目标：**只有真依赖才切遍**。

## 依赖判定要精确（第 3 步第一件，已做）
暗黑2 那 211 次「遍内写缓冲」不是真依赖，是依赖判定太粗：每个缓冲的「本次提交已用区间」只记 8 段、超了并成外包；
19 MB / 12.6 MB / 8 MB 流式缓冲每帧上千个偏移，外包成整块后每次写都判「已用」。Mac 回放暗黑2 录像量（NXGAL_TRACE_BUFW）：外包判命中 4629 / 3675 / 1828 次，精确判 12 / 199 / 0 次。
改成精确区间集（gal_buf.m use_iv，有序、互不相交，二分查找）后测算：暗黑2 每帧 265.7 遍 / 3401 MB → 55.2 遍 / 264 MB，正好等于上表第一层；真机原因计数 d2r_1021162459_2 的「缓冲大于 4 MB」207–249 次 / 帧同源。
所有调度决策都建在依赖判定上，判定先精确，后面的版本化 / 挪动才有意义。

## 规则（「真依赖」的定义）
遍 P 开着时来了操作 X：
- X 的输入是 P 已画出的（附件、P 里绘制写过的存储缓冲 / 图像）→ 真依赖，切。
- X 写的目标被 P 里已有的绘制读过：缓冲 → 换新块（下面的版本化），不算依赖；贴图 → 真依赖（贴图不换块）。
- 其余 → 挪到遍外，不切。
- 自采样（TextureBarrier 后本遍采样自己的附件）→ 帧缓冲读取（gal_prog_fbfetch，画面·着色器线出变体）；拿不到变体才切。
- 内存屏障两侧有存储写冲突、CPU 读回 → 真依赖。换目标组 = 遍边界。

## 机制（第 3 步实现）
1. **两个插入点**（都已有雏形）：
   - 预载段（在录命令缓冲之前）：X 的输入不来自本命令缓冲里的 GPU 工作（CPU 数据、更早提交的结果）→ 放这里。
   - 遍前段（当前遍之前，gal_core.m g_segs）：X 的输入来自本命令缓冲里更早的遍 → 放这里。现在只在用过间接计数绘制时开遍即分段；改为按需：上一帧出现过需要遍前段的操作才分段（不用的游戏不付每遍一个命令缓冲的代价）。
2. **缓冲版本化（写新块、换绑定）**：X 要写的区间已被插入点之后、X 之前的命令读过 → 给这段区间开新版本（临时内存块），X 写进新版本，之后的绑定解析到新版本；版本一旦被绘制读过就不再改，后来的写再开版本。
   本命令缓冲收尾时把最后版本拷回真缓冲（同现在的待拷回）。部分覆盖的绑定：新版本 = 插入点里先拷原区间、再拷 X 的数据（都在插入点内按序）。
   上限：每帧版本总量 ≤ 临时内存一圈（超了这次退回切遍，计数报红）；回收随命令缓冲栅栏（同 gal_transient）。
3. **派发 / 贴图上传 / 贴图拷贝 / 落实清屏 / 索引转换**：按规则判过就录进对应插入点；派发写的缓冲同样走版本化。
4. **同步号**（create_sync 要求提交）：懒同步——记「同步号 → 下次提交的栅栏」，真被等到时才提交；单列，第二批做。
5. **跨遍合并**（第二层）：要整遍重排，需要延后编码；字节收益小，第三批再评估。

## 第 3 步第二件：遍内操作挪到遍前段（perf/sched-hoist）
- 遍前段通用化：触发从「最近用过间接计数」改为「最近 2 帧有操作想挪到遍前」（gal_prepass_want）；遍前段可开渲染编码器（落实清屏用）。
- 依赖判定两层：缓冲「本次提交已用」精确区间集（use）+「本遍已用」外包（upass / uplo / uphi，O(1)，判多不判少）；贴图「本遍用过」戳（写参数时打，参数集复用限同一遍）。
  挪到遍前段的命令绑定时不算本遍用法（g_buf_prepass_bind）。
- 挪动：派发（本遍无存储写、不碰本遍附件、要写的缓冲区间 / 图像本遍没用过；待拷回镜像一并拷回进遍前段，前提是待拷回区间本遍没用过）、
  落实挂起清屏（被清贴图本遍没用过）、贴图上传（目标本遍没用过，数据在 CPU 暂存）。
- 懒同步：遍开着时的 create_sync 挂起，遍收尾时提交回填栅栏；有人等就当场提交（别的线程等也提交——它拿着入口锁，录制线程不在入口里；否则可能死锁）。
  01007EF00011E000实测：派发挪走后切遍原样落到紧跟的同步号上（每帧 +3.1 次「游戏提交」），懒同步与派发必须同批。
- 测算口径修正：独立落实的清屏遍（没开渲染遍时落实）收尾记「遍边界」，不是切遍。
- 单测 t_nobreak 用例 10–14（派发 / 待拷回 / 清屏 / 上传 / 写图像 / 懒同步，含反例与「去掉检查即失败」的反证），Metal 校验层下全过。

## 与现有机制的关系（不留兼容层）
- 镜像（影子 + 待拷回）、暂存补丁、预载拷贝 → 都是「缓冲版本化 + 预载段」的特例，新机制合入后删掉；影子（CPU 全量副本）只在 CPU 侧读需要时保留（索引转换的 CPU 路径）。
- 遍前段：从「间接计数专用」改为通用插入点。
- 两遍合一（换目标组时同附件接着画）：保留，它处理的是遍边界本身。

## 判据
- 九款「无真依赖的切遍」每帧 0 次（本测算工具读数，「可重排」一栏归零）。
- 九款录像画面逐帧不退（合并关 / 开同法：差异不超过同配置自比噪声）。
- CPU 编码时间不涨超过噪声（同录像回放 NXGAL_PERF_TIME 拆账对比）。
